# Правила для ИИ-агентов

Эти инструкции действуют на весь репозиторий. Явные указания пользователя по текущей задаче имеют приоритет.

## Перед работой

1. Прочитай `README.md` и `docs/architecture.md`, затем файлы, относящиеся к задаче. Не перечитывай неизменённую документацию без необходимости.
2. Проверь `git status --short --branch` и существующие изменения. Отличай свою работу от работы пользователя и других агентов.
3. Выполни понятную задачу целиком: изменение, необходимые проверки, краткий отчёт. Не ограничивайся планом, если запрошена реализация.
4. Уточняй только существенные неоднозначности. Обычные обратимые правки, чтение файлов и проверки в рамках задачи не требуют отдельного подтверждения.

## Устройство проекта

Это браузерный редактор цифровых схем на JavaScript ES modules без сборки и зависимостей.

| Файл | Что изменять здесь |
| --- | --- |
| `simulator.js` | Типы компонентов, вычисление и распространение сигналов, валидация документов |
| `geometry.js` | Сетка, пины, маршруты и точки ответвлений |
| `app.js` | Состояние редактора, инструменты, события DOM, история и хранение |
| `examples.js` | Демонстрационные схемы |
| `index.html`, `style.css` | Разметка, интерфейс и оформление |
| `tests/` | Автоматические проверки логики и геометрии |
| `scripts/check-browser.mjs` | Проверки реальных действий пользователя через Chrome DevTools |

Не добавляй фреймворк, сборку или зависимости без необходимости для задачи. Не смешивай DOM с чистыми модулями симуляции и геометрии. Пользовательские сообщения пиши по-русски, имена функций и модулей — по-английски.

## Инварианты, которые нельзя сломать

- Симуляция начинается с предыдущих значений выходов. NOR/NAND RS-триггер сохраняет Q после снятия set/reset. Начальное неизвестное состояние не заменяется произвольным 0 или 1.
- Различай 0, 1, X (неизвестно) и Z (нет сигнала). Колебания одной цепи не должны обнулять независимые цепи.
- Рендер, масштабирование, перемещение компонентов, изменение меток и маршрутов не сбрасывают память и не требуют электрического пересчёта.
- История хранит модель и состояние вместе. Одно перетаскивание — одна операция отмены. Undo/redo, пауза, продолжение, импорт и автосохранение должны согласованно работать с состоянием.
- Электрическое соединение задаётся пинами. Пересечение линий не создаёт соединение. Ответвление сейчас имеет тот же источник и самостоятельный маршрут.
- Каждый вход имеет не более одного драйвера; выход может иметь много потребителей.
- Перетаскивание не выделяет текст страницы. Координаты учитывают масштаб и сдвиг поля; завершай жесты при отмене и потере захвата указателя.
- Подписи пользователя экранируются при вставке в HTML/SVG. JSON считается внешним вводом: новые поля проверяются в `validate`.
- Старые сохранённые схемы продолжают открываться. Несовместимое изменение формата требует новой версии, миграции и проверки старого документа. Поля `points` и `state` необязательны в версии 1.

Если задача намеренно меняет один из этих контрактов, явно отрази это в реализации, документации и тестах.

## Объём и качество изменений

- Решай текущую задачу без несвязанных переписываний. Сохраняй существующее поведение вне согласованного изменения.
- Пиши новые участки читаемо. Не переформатируй весь плотный существующий код вместе с небольшим багфиксом.
- Сначала найди причину ошибки. Не скрывай её отключением проверок, произвольными значениями или удалением теста.
- Для ошибки симулятора добавь регрессионный сценарий с наблюдаемым результатом. Для интерфейса проверяй пользовательское действие, а не только наличие строки в исходнике.
- Обновляй README при изменении управления или запуска; архитектурную справку — при изменении модели или формата.

## Проверки

Все команды запускаются из корня проекта. Node.js 22+; для сервера нужен Python 3.

```sh
npm start              # http://localhost:5173
npm run check          # синтаксис JavaScript и автоматические тесты
npm run test:browser   # интерфейс в отдельном тестовом Chrome
```

После изменений JavaScript выполни `npm run check`. После изменений инструментов, жестов, хранения или истории дополнительно выполни браузерную проверку по README, если доступен Chrome. Она использует глобальный WebSocket Node.js и отдельный браузерный профиль.

Нельзя запускать браузерную проверку против рабочего профиля пользователя: она очищает начальное автосохранение тестового профиля. Не открывай личный профиль ради проверки приложения.

Для документации и небольших стилевых правок не создавай искусственные тесты. Если проверка недоступна, сообщи конкретную причину; не выдавай проверку синтаксиса за тест интерфейса. После достаточных успешных проверок заверши задачу.

## Git и совместная работа агентов

- Не откатывай и не затирай чужие изменения. Не применяй `reset --hard`, `clean`, force push и массовое восстановление файлов без прямого указания пользователя.
- Если изменения пересекаются с чужой незавершённой работой, сначала изучи их; при неразрешимом конфликте уточни дальнейшее действие.
- Добавляй в индекс конкретные файлы задачи, проверяй staged diff и `git diff --cached --check` перед коммитом.
- Создавай коммит, когда это запрошено или входит в явно заданный процесс. Сообщение описывает результат: `fix: preserve RS latch state`.
- Не публикуй репозиторий, не отправляй коммиты и не меняй remote без соответствующего запроса. Локальный коммит не означает разрешение на push.
- Не меняй глобальную конфигурацию Git, авторство и лицензию проекта по собственной инициативе.
- Не коммить секреты, `.env`, личные настройки, браузерные профили, логи и тестовые снимки. Соблюдай `.gitignore`.

## Итоговый ответ

Кратко опиши, что изменилось, что проверено и что осталось ограничением. Если создан коммит — укажи его хеш. Различай локальную работу и публикацию на сервере. Не утверждай полную совместимость с Logisim: вложенные схемы, многобитные шины, RAM и `.circ` пока не поддерживаются.
